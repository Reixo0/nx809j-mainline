# Mainline Linux on the Nubia RedMagic 11 Pro (NX809J)

SoC: Snapdragon 8 Elite Gen 5 — upstream **Kaanapali** (SM8850), downstream `canoe`,
`soc_id` 660 rev 2.0, board-id 8 (MTP-derived). Panel: BF375 Raydium RM692H5,
1216×2688, DSC command mode.

## Layout

| Path | What |
|---|---|
| `linux/` | linux-next checkout (its own git repo). Board work lives here. |
| `linux/arch/arm64/boot/dts/qcom/kaanapali-nubia-nx809j.dts` | Board DTS (derived from `kaanapali-qrd.dts`) |
| `configs/nx809j.config` | Kconfig fragment merged over arm64 `defconfig` |
| `initramfs/init` | Bring-up init: fb console + USB NCM telnet at 172.16.42.1 |
| `scripts/dump-phone.sh` | Dump partitions, live DT, dmesg, debugfs, firmware via adb root |
| `scripts/split-dtbs.py` | Split + decompile concatenated DTBs (vendor_boot, dtbo) |
| `scripts/compare-regulators.py` | Diff RPMh regulator ranges: downstream live DT vs upstream dts |
| `scripts/build.sh` | `config` / `kernel` / `dtbs` / `modules` / `all` (clang, `LLVM=1`) |
| `scripts/pack-firmware.py` | Squash `.mdt` → `.mbn`, lay out `/lib/firmware/qcom/...` |
| `shim/` | Boot shim placed in front of the kernel: merges ABL's memory/initrd/kaslr into our DTB (`shim/build.sh`, host test `shim/test-merge.c`) |
| `scripts/mkboot.sh` | Build `out/boot.img` for flashing to `boot_a`: header v4, shim + kernel (gzip) + appended DTB, os_version 16.0.0/2026-08, AVB footer |
| `probe/` | Tiny boot-path probes (PSCI off/reset), `probe/build.sh <name>` |
| `scripts/boot.sh` | `fastboot boot out/boot.img` from superfastboot (RAM boot). **Never reaches the kernel** on this phone (see notes) |
| `scripts/get-pstore.sh` | After a hang, from Android: save the previous kernel's ramoops log and tell if it was mainline |
| `dump/` | Device dumps — **private** (IMEI/EFS in `modemst*`, `persist`, keys). Not in git. |
| `out/panel/` | Panel drivers generated by linux-mdss-dsi-panel-driver-generator |

## Setup

Host tools: clang/LLVM (`LLVM=1` build, no cross gcc), `dtc`/`fdtget`,
`adb`/`fastboot`, `lz4`, `cpio`, `mtools`, Python 3. Third-party pieces go
under `tools/` (not in git):

```bash
git clone --depth=1 https://git.kernel.org/pub/scm/linux/kernel/git/next/linux-next.git linux
git clone --depth=1 https://android.googlesource.com/platform/system/tools/mkbootimg tools/mkbootimg
git clone --depth=1 https://android.googlesource.com/platform/external/avb tools/avb
git clone --depth=1 https://github.com/msm8916-mainline/linux-mdss-dsi-panel-driver-generator tools/panel-gen
```

Static arm64 busybox: `bin/busybox.static` from Alpine's `busybox-static`
apk (aarch64), extracted to `tools/dl/busybox/`. The kernel changes live on
the `nx809j` branch of `linux/`.

Device dumps and firmware come from the phone itself (`scripts/dump-phone.sh`,
`scripts/pack-firmware.py`); they are not redistributable and stay out of git.

## Workflow

```bash
scripts/build.sh            # first run also generates the config
scripts/mkboot.sh
scripts/boot.sh
```

If the board is alive you get kernel messages on screen and, once USB probes,
the host sees an NCM network device with a raw shell on 172.16.42.1:23 (`nc`,
no DHCP). Give the host side a static address once:

```bash
nmcli connection add type ethernet ifname <usb-iface> con-name nx809j-usb ipv4.method manual ipv4.addresses 172.16.42.2/24 ipv4.never-default yes ipv6.method ignore
```

then run commands with `scripts/phone-sh.py 'dmesg | tail'`.

To recover: hold power ~15 s; the phone reboots into the untouched Android install.

Read logs from a failed boot after returning to Android:

```bash
adb shell su -c 'cat /sys/fs/pstore/*'
```

## Notes / known unknowns for first boot

- **Boot path:** the stock fastboot refuses `boot`; use the efisp/gbl-chainload
  superfastboot (vol-up during boot). Header v2 images are rejected with
  `Failed to load/authenticate boot image: Invalid Parameter`, so images are
  header v4 with the DTB appended to `Image.gz` (same layout Mu-Silicium uses on
  the OnePlus 15, which has the same msm-id/board-id). ABL still pulls in
  `vendor_boot` from the partition: its ramdisk, cmdline and bootconfig get
  merged with ours, hence `rdinit=/nx809j-init` and busybox under `/nx809j/`.
  Our files went missing from that merged ramdisk (no error logged), so the
  bring-up initramfs is **built into the kernel** (`scripts/mkinitramfs.sh`,
  `CONFIG_INITRAMFS_SOURCE`); the boot.img ramdisk is just a copy.
- **Logs:** init echoes to the kernel log too. `panic=10` makes panics warm-
  reboot so RAM (pstore) survives; a long power press often loses it.
- **`fastboot boot` is a dead end here:** a probe that only does a PSCI reset
  hangs on the logo, so superfastboot never hands control to the kernel.
  Testing moves to writing `boot_a` (probes in `probe/`, built by
  `probe/build.sh <name>`), restoring `dump/partitions/boot_a.img` after.
- **Normal boot path works, but ABL passes the downstream DTB** from
  `vendor_boot` in x0 and ignores the one appended to the kernel (proven
  with probes). Hence `shim/`: it merges `/memory` reg and `/chosen`
  initrd/kaslr/rng from ABL's DTB into our embedded one, then jumps to Linux
  at +2 MiB. Shim failure = PSCI reset (boot loop). `SHIM=shim-off` builds a
  variant that powers off after a successful merge.
- **Flash/restore** from superfastboot: `fastboot flash boot_a out/boot.img`,
  restore with `fastboot flash boot_a dump/partitions/boot_a.img`.
- **Failed loads disable slot a.** Recovery, by hand from superfastboot:
  `fastboot set_active a`, then `fastboot reboot`. Never activate slot b:
  it has never booted and runs its own, possibly older, `abl_b`.
- **Display:** `simple-framebuffer` at the cont-splash region `0xfc800000`.
  `clk_ignore_unused pd_ignore_unused` keep the display pipeline running.
  It's a command-mode panel, so the image may freeze if MDP autorefresh is off.
- **UART:** `uart7` is kept as in QRD; no known accessible test points yet.
- **Disabled for now:** GPU, ADSP/CDSP (firmware paths set to
  `qcom/kaanapali/nubia/nx809j/`), SD controller, flash LED, RGB PWM LED.
- **Reserved GPIOs:** 40-43, 74, 119-120, 144-147 (from downstream
  `qcom,gpios-reserved`). Touching them crashes the device.

## Bring-up checklist

- [x] Boots, framebuffer console visible (via shim, boot_a)
- [x] UFS: all LUNs and partitions enumerate (nothing mounted yet)
- [x] USB gadget networking, shell via `scripts/phone-sh.py`
- [x] cpufreq via SCMI (cpucp mailbox built in): 384 MHz-3.63 GHz / 768 MHz-4.40 GHz
- [ ] pm8010 (SPMI1 SID 0xc/0xd) and pmd802x (SID 4) don't answer on SPMI
- [ ] Buttons (vol up GPIO 101, vol down = PON resin, power)
- [x] SoCCP (attached; pmic-glink lives here on Kaanapali) and ADSP (loaded from built-in firmware)
- [x] Battery/charger via battmgr, USB-C via UCSI (role switching still forced to device mode)
- [ ] CDSP
- [ ] Display (MSM DRM + RM692H5 panel driver from `out/panel/`)
- [ ] GPU (Adreno 840, `gen80200_*`)
- [ ] Touchscreen, haptics (AW86320), fan, shoulder triggers
- [ ] Audio, Wi-Fi/BT ("peach" firmware, over PCIe), modem, cameras
