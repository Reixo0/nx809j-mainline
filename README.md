# Mainline Linux on the Nubia RedMagic 11 Pro (NX809J)

SoC: Snapdragon 8 Elite Gen 5 — upstream **Kaanapali** (SM8850), downstream `canoe`,
`soc_id` 660 rev 2.0, board-id 8 (MTP-derived). Panel: BF375 Raydium RM692H5,
1216×2688, DSC command mode.

## Setup

Host tools: clang/LLVM (`LLVM=1` build, no cross gcc), `dtc`/`fdtget`,
`adb`/`fastboot`, `lz4`, `cpio`, `mtools`, Python 3. Third-party pieces go
under `tools/` (not in git):

```bash
git clone --depth=1 https://git.kernel.org/pub/scm/linux/kernel/git/next/linux-next.git linux
git clone --depth=1 https://android.googlesource.com/platform/system/tools/mkbootimg tools/mkbootimg
git clone --depth=1 https://android.googlesource.com/platform/external/avb tools/avb
git clone --depth=1 https://github.com/msm8916-mainline/linux-mdss-dsi-panel-driver-generator tools/panel-gen
```

Then apply the kernel patches (made against `next-20261022`):

```bash
git -C linux switch -c nx809j && git -C linux am ../patches/*.patch
```

Static arm64 busybox: `bin/busybox.static` from Alpine's `busybox-static`
apk (aarch64), extracted to `tools/dl/busybox/`. The kernel changes live on
the `nx809j` branch of `linux/`.

Device dumps and firmware come from the phone itself (`scripts/dump-phone.sh`,
`scripts/pack-firmware.py`); they are not redistributable and stay out of git.

## Workflow

```bash
scripts/build.sh            # first run also generates the config
scripts/mkboot.sh
scripts/boot.sh
```

If the board is alive you get kernel messages on screen and, once USB probes,
the host sees an NCM network device with a raw shell on 172.16.42.1:23 (`nc`,
no DHCP). Give the host side a static address once:

```bash
nmcli connection add type ethernet ifname <usb-iface> con-name nx809j-usb ipv4.method manual ipv4.addresses 172.16.42.2/24 ipv4.never-default yes ipv6.method ignore
```

then run commands with `scripts/phone-sh.py 'dmesg | tail'`.

To recover: hold power ~15 s; the phone reboots into the untouched Android install.

Read logs from a failed boot after returning to Android:

```bash
adb shell su -c 'cat /sys/fs/pstore/*'
```

## Root filesystem inside super (fast, no PC needed)

postmarketOS can live in a logical partition `linux_root` inside `super`'s free
space (12.8 GiB free on stock layout). Android's partitions and `userdata` are
not touched. The kernel maps it with dm-init from the cmdline.

```bash
scripts/make-super-image.sh 9G                    # phone off / image unused
# phone: superfastboot -> `fastboot reboot recovery` -> "Enter fastboot"
fastboot getvar is-userspace                      # yes
fastboot getvar snapshot-update-status            # none / merged
fastboot create-logical-partition linux_root 9663676416
fastboot flash linux_root out/pmos/linux_root.simg
# boot any mainline image once, then read super's metadata (read-only):
ssh reixo@172.16.42.1 'sudo dd if=/dev/sda7 bs=4096 count=256' > super-head.bin
scripts/mkboot.sh nx809j.root=dm "$(scripts/super-dm-cmdline.py super-head.bin)"
fastboot flash boot_a out/boot.img                # from superfastboot
```

Back up `super`'s first 1 MiB (its partition tables) before creating the
partition. A full ROM flash that rewrites `super` removes `linux_root`; OTAs
need some free space in `super` for snapshots.

## postmarketOS over USB (Android untouched)

The rootfs lives on the PC and the phone mounts it over NBD across the USB
network. Android's userdata is metadata-encrypted (TEE keys), so mainline
can't use space there; nothing here writes to the phone's UFS.

One-time setup:

```bash
sudo pacman -S pmbootstrap
pmbootstrap --aports ~/nx809j_linux/tools/pmaports init   # edge, nubia, nx809j, console
sudo scripts/host-usb-nat.sh                              # ufw: NBD port + NAT for the phone
```

Build and run:

```bash
scripts/build.sh && scripts/pmos-kernel-pkg.sh
pmbootstrap install --split
scripts/pmos-prepare-root.sh                              # -> out/pmos/nubia-nx809j-root.img
scripts/mkboot.sh nx809j.root=nbd                         # boot image that switch_roots to NBD
scripts/nbd-root.sh                                       # keep running while pmOS is up
fastboot flash boot_a out/boot.img
ssh <user>@172.16.42.1
```

Notes:
- The phone's init waits up to a minute for the server, then falls back to
  the busybox shell (`scripts/phone-sh.py`).
- `nbd-root.sh` allows multiple clients: a hard-reset phone leaves a dead
  connection behind that would block the next boot otherwise.
- `usb0` is unmanaged by NetworkManager (losing it would drop the rootfs);
  `nx809j-usb-uplink.service` sets the default route via the PC and DNS.
- Shut down with `sudo poweroff` rather than holding power.

## Notes / known unknowns for first boot

- **Boot path:** the stock fastboot refuses `boot`; use the efisp/gbl-chainload
  superfastboot (vol-up during boot). Header v2 images are rejected with
  `Failed to load/authenticate boot image: Invalid Parameter`, so images are
  header v4 with the DTB appended to `Image.gz` (same layout Mu-Silicium uses on
  the OnePlus 15, which has the same msm-id/board-id). ABL still pulls in
  `vendor_boot` from the partition: its ramdisk, cmdline and bootconfig get
  merged with ours, hence `rdinit=/nx809j-init` and busybox under `/nx809j/`.
  Our files went missing from that merged ramdisk (no error logged), so the
  bring-up initramfs is **built into the kernel** (`scripts/mkinitramfs.sh`,
  `CONFIG_INITRAMFS_SOURCE`); the boot.img ramdisk is just a copy.
- **Logs:** init echoes to the kernel log too. `panic=10` makes panics warm-
  reboot so RAM (pstore) survives; a long power press often loses it.
- **`fastboot boot` is a dead end here:** a probe that only does a PSCI reset
  hangs on the logo, so superfastboot never hands control to the kernel.
  Testing moves to writing `boot_a` (probes in `probe/`, built by
  `probe/build.sh <name>`), restoring `dump/partitions/boot_a.img` after.
- **Normal boot path works, but ABL passes the downstream DTB** from
  `vendor_boot` in x0 and ignores the one appended to the kernel (proven
  with probes). Hence `shim/`: it merges `/memory` reg and `/chosen`
  initrd/kaslr/rng from ABL's DTB into our embedded one, then jumps to Linux
  at +2 MiB. Shim failure = PSCI reset (boot loop). `SHIM=shim-off` builds a
  variant that powers off after a successful merge.
- **Flash/restore** from superfastboot: `fastboot flash boot_a out/boot.img`,
  restore with `fastboot flash boot_a dump/partitions/boot_a.img`.
- **Failed loads disable slot a.** Recovery, by hand from superfastboot:
  `fastboot set_active a`, then `fastboot reboot`. Never activate slot b:
  it has never booted and runs its own, possibly older, `abl_b`.
- **Display:** `simple-framebuffer` (cont-splash at `0xfc800000`) until MSM DRM
  takes over with the RM692H5 driver. The panel decodes DSC with its own
  config (page `0xd2`); RC range 0 is patched to the VESA value the kernel
  encoder uses, otherwise the picture is corrupted.
- **UART:** `uart7` is kept as in QRD; no known accessible test points yet.
- **Disabled for now:** CDSP, SD controller, flash LED, RGB PWM LED.
- **GPU:** with CLX on, the GMU used to time out on its first GX power vote.
  The cause was rpmhpd pinning the gfx/gmxc rails at their top level until
  sync_state (which never came, partly because upstream placed the GMU at
  0x3d6c000 instead of 0x3d37000): patches 0027-0028 from the iceland queue
  fix both, and the GPU now runs with the upstream CLX and limits tables.
- **Wi-Fi wake-on-packet:** the firmware side works (`iw phy phy0 wowlan enable
  magic-packet patterns <mac>`: it keeps the link through s2idle, offloads
  ARP/NS/GTK and reports `WOW_REASON_PATTERN_MATCH_FOUND`), but the SoC does
  not wake: PCIe WAKE# (GPIO 104), the downstream "dev SOL" GPIO 205 and GPIO 19
  stay quiet. The PCIe link stays up in s2idle, so the chip signals in-band
  (MSI), which is not a wakeup source; Android takes the link down instead.
- **Reserved GPIOs:** 40-43, 74, 119-120, 144-147 (from downstream
  `qcom,gpios-reserved`). Touching them crashes the device.

## Bring-up checklist

- [x] Boots, framebuffer console visible (via shim, boot_a)
- [x] RTC: the PMIC counter is read only from Linux; the UTC offset lives in 4 bytes of SDAM2 (0x7c, patch 0040), stored by the NTP sync / `hwclock -w`, so the clock is right from boot and RTC alarms wake from suspend
- [x] Suspend: s2idle (`mem_sleep_default=s2idle`), woken by the power key or an RTC alarm; Wi-Fi, Bluetooth and the ADSP resume. PSCI "deep" returns at once on this firmware
- [x] UFS: all LUNs and partitions enumerate (nothing mounted yet)
- [x] USB gadget networking, shell via `scripts/phone-sh.py`
- [x] cpufreq via SCMI (cpucp mailbox built in): 384 MHz-3.63 GHz / 768 MHz-4.40 GHz, plus 4.51 and 4.61 GHz boost steps on the prime cores (enabled at boot by a tmpfiles entry; under sustained load the CPU firmware soon lowers the limit to about 4.26 GHz, at 38 °C)
- [ ] pm8010 (SPMI1 SID 0xc/0xd) and pmd802x (SID 4) don't answer on SPMI
- [x] Buttons: power + volume down (PMIC PON, `POWER_RESET_QCOM_PON=y`), volume up (GPIO 101), game slider (GPIO 97, `SW_PEN_INSERTED`, 1 = down)
- [x] SoCCP (attached; pmic-glink lives here on Kaanapali) and ADSP (loaded from built-in firmware)
- [x] Battery/charger via battmgr, USB-C via UCSI
- [x] USB-C data roles (patches 0041-0059): pmic-glink/UCSI switches the controller between device mode (USB network shell to the PC) and host mode (game controllers, drives) on its own. SuperSpeed works: an NVMe enclosure enumerates at 10 Gbit/s and reads at about 530 MB/s. Needs a USB 3 cable; the cable in the box is USB 2 only, so the PC link stays at 480 Mbit/s. The GCC pipe clock input of the USB3 PHY was missing from `kaanapali.dtsi` (patch 0058). exFAT and NTFS (ntfs3) are modules
- [x] postmarketOS Plasma Mobile: rootfs in `super` (linux_root, dm-init) or over NBD from the PC; internet via the PC
- [ ] CDSP
- [x] Display: MSM DRM + `panel-raydium-rm692h5` (DSC, 60 Hz), brightness, blank/unblank
- [x] Display: 60, 90, 120 and 144 Hz modes (patches 0060-0066), picked in Settings → Display; the panel gets 144 frames per second (vkmark). The msm DSI host sized the DSC link of this 10 bpc command mode panel 30/24 too slow, which held every rate to ~60 frames per second (patch 0065). Browsers (Qt WebEngine) still animate at 60
- [x] GPU: Adreno 840, Mesa freedreno GLES 3.2 (kmscube) and Turnip Vulkan 1.4 (vkmark 31407), with CLX and limits enabled as upstream. GMU/SQE from linux-firmware in `tools/dl/linux-firmware`, firmware in the rootfs via `scripts/pmos-add-firmware.sh`
- [x] Touchscreen: Synaptics S3910 (TouchComm v1) on SPI19, multitouch; driver = upstream v2 TCM I2C series + our SPI support
- [x] Fan and liquid cooling pump (patches 0108-0109): the fan is a 25 kHz PWM fan on a PMH0101 LPG channel (output inverted at PMIC GPIO9, L8B supply, tachometer on GPIO211, 3 pulses per turn), driven by mainline `pwm-fan` (about 22,000 RPM at full speed). The micropump is an Awinic AWP1921 piezo driver on I2C5 (0x44); our `awp1921` driver follows the stock register sequence and has the stock off/low/mid/high levels. Both are cooling devices of the prime core and GPU thermal zones: fan levels 1-5 from 45 to 65 °C, pump low/mid/high from 50 to 60 °C, 4 °C hysteresis. Manual control: hwmon `pwm1` or `cooling_device*/cur_state`
- [ ] Haptics (AW86320), shoulder triggers, LEDs (aw22xxx: logo, shoulders, fan)
- [x] Wi-Fi: Qualcomm "peach" (WCN7880, PCI 17cb:110e) on PCIe0 with ath12k (patches 0017-0021): window register 0x3278, aux_ucode + QDSS trace config download, cold boot calibration (8.3 s at boot), RF rail voltages from downstream, its own REO/TCL register offsets and 32-bit TLVs (QCC2072 HAL). Connects with WPA2 through NetworkManager; ~475 Mbit/s down / 280 Mbit/s up on a 5 GHz LAN. Firmware is not in linux-firmware: `scripts/install-wifi-firmware.sh` copies the phone's own files (dumped from Android's /vendor/firmware_mnt/image/peach) into ath12k/PEACH/hw2.0
- [x] Bluetooth: the Brahma half of the combo (product 0x21) on UART18, as a WCN7860 (patches 0022-0026, from the OnePlus 15 / Pad 4 work, see Credits): the controller needs a PERI baud rate command before the speed change, then takes the ELF rampatch qca/brhbtfw20.mbn and qca/brhbtnv20.bin. Its public address comes from persist (`nx809j-bt-addr.service`, read only). Scans and is the default controller in bluetoothctl
- [x] Speakers (patches 0067-0073): two Awinic AW88461 amplifiers on i2c_hub_3, fed from primary MI2S data line SD1 (SD0 carries their feedback), stock tuning from `aw882xx_acf.bin`. Sound card "Nubia-NX809J", our topology, and a UCM profile in the device package, so PipeWire and Plasma show a speaker output with working volume. 32-bit streams play silence on the speakers, so their stream is 16-bit
- [x] Microphone (patches 0074-0088): the WCD9395 codec on SoundWire (RX swr1, TX swr2, as on the MTP), bottom mic = analog AMIC4, a "Mic" input in the UCM profile. The other analog inputs: AMIC3 (back or side) and AMIC5 (weak) pick up sound, AMIC1 does not
- [x] Headphones (patches 0089-0102): the WCD9395 headphone amplifier in HPH PCM (HiFi) mode, as stock, over SoundWire port 9 (HPH PCM patches from the KONKR Pocket FIT / SM8750 work, see Credits). It needed the SoundWire stream synchronization point period programmed (patch 0094) and a 24-bit RX codec DMA (patch 0095; 16-bit delivers nothing). The headphone stream is 32-bit, so software volume keeps the low bits: with 16-bit, low volume crackled. A class-H fix (patch 0102) removed background static. Plugging and unplugging switches between the Headphones and Speaker outputs on its own. Use the PipeWire audio backend (`apk add postmarketos-base-ui-audio-backend-pipewire`, which replaces the PulseAudio one): it picks the 32-bit format on its own
- [x] USB audio: a game controller's headphone port works (snd-usb-audio)
- [x] Headset mic (patches 0103-0107): the 3.5 mm jack's mic and ground run through the WCD9395 USB-SS switch (i2c3, 0x0e), as on stock; without it the ground floats and headsets screech. The switch driver gets a headset jack mode (USB passes through, jack switches on, ground/mic swapped for OMTP/CTIA headsets), with the register sequence of the downstream driver, and MBHC picks the wiring before reporting. The headset limit had to be scaled for the 2.7 V mic bias (2.55 V; a headset mic sits near 2.1 V). Plugging a headset switches the output to Headphones and the input to "Headset microphone" (AMIC2); the UCM splits the stereo capture PCM by channel (bottom mic 0, headset mic 1), since PipeWire keeps devices on one PCM in separate profiles. Also fixes a mainline register address (MG2_MISC, patch 0103)
- [ ] Audio: earpiece use of the top speaker (stock Receiver profile in the ACF), headset buttons untested
- [x] Modem and mobile data (patches 0110-0121): the modem boots from the phone's own firmware (Kaanapali modem patches by Victor Fuentes and two QRTR fixes from the iceland queue, see Credits), registers on LTE and 5G NR, and ModemManager brings up mobile data through IPA v5.5. IPA needed the Kaanapali settings of the downstream driver: its own endpoint numbers, SRAM layout, DDR write limit and SMEM size, three extra TLVs in the modem init request, and a marker in the microcontroller descriptor RAM (without it, starting the microcontroller froze the whole SoC). Its DMA is held to IOVAs 0x20000000-0x3fffffff as on stock (above that, UFS stalled under load) and its interrupt is level triggered (edge lost downlink wakeups). The modem's file system is served by rmtfs from **copies** of modemst1/modemst2/fsc/fsg in `/var/lib/rmtfs`, so Linux never writes Android's partitions; `rmtfs -s` starts the modem at boot. Operator DNS servers (Orange ES) strip DNSSEC signatures, so systemd-resolved needs `DNSSEC=no`
- [ ] Modem crash recovery: stopping the modem works, but starting it again freezes the SoC (the IPA microcontroller is still running from the first boot), so recovery is disabled by a udev rule and a crashed modem stays down until reboot
- [x] Dual boot with Android: Android keeps `boot_a` and boots by default through the [Canoe](https://github.com/1vivy/gbl_root_canoe) boot manager in `efisp`; Linux starts from Canoe's menu or, without any menu, through its boot-once record (`nx809j-reboot-linux` on Linux; on Android a KernelSU module or **Linux** in the power menu, from [android-reboot-to-linux](https://github.com/Reixo0/android-reboot-to-linux)), via Mu-Silicium and systemd-boot. See [uefi/README.md](uefi/README.md#dual-boot-with-canoe). `reboot bootloader`/`recovery` from Linux reach the bootloader through the PMIC restart reason (patch 0122)
- [ ] Voice call audio, SMS, GPS
- [ ] Cameras
